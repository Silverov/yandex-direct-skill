# Стратегии ставок Яндекс Директа

Актуально на октябрь 2026, для Единой перфоманс-кампании (ЕПК). Текстово-графические кампании, динамические
объявления и смарт-баннеры переведены в ЕПК; новые ТГО через API создаются как ЕПК в режиме совместимости.

## Стратегии ЕПК: интерфейс ↔ API

Стратегия задаётся отдельно для поиска и сетей: `BiddingStrategy.Search` и `BiddingStrategy.Network`, у каждой
`BiddingStrategyType` и вложенный объект с параметрами. Деньги в API — в микроединицах (× 1 000 000).

| Интерфейс | Оплата | `BiddingStrategyType` | Объект и ключевые параметры |
|-----------|--------|-----------------------|-----------------------------|
| Максимум кликов | за клики | `WB_MAXIMUM_CLICKS` | `WbMaximumClicks`: недельный бюджет `WeeklySpendLimit`, `BidCeiling` |
| Максимум кликов (средняя цена клика) | за клики | `AVERAGE_CPC` | `AverageCpc`: `AverageCpc`, `WeeklySpendLimit` |
| Максимум конверсий | за клики | `WB_MAXIMUM_CONVERSION_RATE` | `WbMaximumConversionRate`: `GoalId`, `WeeklySpendLimit`, `BidCeiling` |
| Максимум конверсий (средняя цена конверсии) | за клики | `AVERAGE_CPA` | `AverageCpa`: `AverageCpa`, `GoalId`, `WeeklySpendLimit`, `BidCeiling`, `ExplorationBudget` |
| Максимум конверсий (цена конверсии) | за конверсии | `PAY_FOR_CONVERSION` | `PayForConversion`: `Cpa`, `GoalId`, `WeeklySpendLimit` |
| Максимум конверсий (доля рекламных расходов) | за клики | `AVERAGE_CRR` | `AverageCrr`: `Crr`, `GoalId`, `WeeklySpendLimit`, `ExplorationBudget` |
| Максимум конверсий (ДРР) | за конверсии | `PAY_FOR_CONVERSION_CRR` | `PayForConversionCrr`: `Crr`, `GoalId`, `WeeklySpendLimit` |
| Максимум конверсий по нескольким целям | за клики | `AVERAGE_CPA_MULTIPLE_GOALS` | цели и цены — в `PriorityGoals` кампании; `WeeklySpendLimit`, `BidCeiling` |
| Максимум конверсий по нескольким целям | за конверсии | `PAY_FOR_CONVERSION_MULTIPLE_GOALS` | цели и цены — в `PriorityGoals`; `WeeklySpendLimit` |
| Максимум прибыли | за клики (после выхода из беты — и за конверсии) | `MAX_PROFIT` | `MaxProfit`: `WeeklySpendLimit`, `ExplorationBudget`; цели — в `PriorityGoals`, нужна средняя маржа с конверсии (подробности — в справке Директа) |
| Максимум кликов с ручными ставками | за клики | `HIGHEST_POSITION` (только поиск) | `HighestPosition`: `WeeklySpendLimit`; ставки — на фразах |
| Показы в сетях выключены | — | `SERVING_OFF` | — |

Названия в колонке «Интерфейс» — из справки и мастера настройки кампании. В таблице кампаний веб-интерфейса
(колонка «Бюджет и стратегия») стратегии подписаны по-старому: «Оптимизация кликов» — кликовые стратегии
(`WB_MAXIMUM_CLICKS`, `AVERAGE_CPC`), «Оптимизация конверсий» — конверсионные (`WB_MAXIMUM_CONVERSION_RATE`,
`AVERAGE_CPA`, `PAY_FOR_CONVERSION`, ДРР, мультицелевые). Так это выглядит в октябре 2026 даже у ЕПК, созданных
в июле 2026. Точный тип — `BiddingStrategyType` в API или настройки кампании.

Чего в ЕПК нет:
- ручных ставок в РСЯ (`MAXIMUM_COVERAGE`) — отключены 01.07.2024;
- `AVERAGE_ROI` (рентабельность) — вместо неё ДРР (`AVERAGE_CRR`, `PAY_FOR_CONVERSION_CRR`) или «Максимум прибыли»;
- `WEEKLY_CLICK_PACKAGE`, `IMPRESSIONS_BELOW_SEARCH`.

Даты появления: `AVERAGE_CPA_MULTIPLE_GOALS` и `PAY_FOR_CONVERSION_MULTIPLE_GOALS` — июнь 2025,
`MAX_PROFIT` — в API с сентября 2025.

## Бюджет

- Бюджет недельный (`WeeklySpendLimit`), минимум 300 ₽ в неделю; неделя — с понедельника по воскресенье.
  Для флайтов — бюджет на период (`CustomPeriodBudget`, `BudgetType` = `CUSTOM_PERIOD_BUDGET`).
- С 22.06.2026 кампании с ручными ставками и общий счёт тоже переведены на недельный бюджет: прежний дневной
  пересчитан в недельный с учётом расписания. Поле `DailyBudget` в API осталось — ориентироваться на `WeeklySpendLimit`.
- С 06.07.2026 в кампаниях с оплатой за клики остаток бюджета частично (до 30% недельного) переносится на следующую
  неделю (`WeeklyBudgetRollover`), отключить перенос нельзя.
- В стратегиях с оплатой за клики за один день тратится не больше 35% недельного бюджета; без корректировок ставка
  не поднимается выше 10% недельного бюджета.
- Оплата за конверсии: недельный бюджет ≥ 10 × цена конверсии.

## Обучение и перезапуски

- Цель для конверсионной стратегии должна достигаться не реже 10 раз в неделю. Обучение занимает 1–2 недели
  и дольше; на низкочастотных запросах — дольше.
- Перезапуск обучения: смена стратегии, типа ограничения расходов или модели оплаты; пауза кампании дольше 7 дней.
- Статистика стратегии сбрасывается, если она не работала больше 28 дней.
- Изменение бюджета и добавление или удаление регионов обычно вызывают переобучение, а не перезапуск.

Отсюда правило аудита: в первые 2–3 недели после запуска или перезапуска стратегию, ограничения и модель оплаты
не трогать.

## Пакетные стратегии

Сервис `Strategies` (с 2023): одна стратегия на несколько кампаний, в ЕПК можно объединять кампании с текстовыми
и товарными объявлениями. Решение для мелких кампаний, каждая из которых не набирает 10 конверсий в неделю.
У кампании это видно по `PackageBiddingStrategy`.

## Дерево выбора стратегии

```
Есть ценность конверсии и понятная средняя маржа (e-com)?
├── Да → «Максимум прибыли» или ДРР (AVERAGE_CRR / PAY_FOR_CONVERSION_CRR)
└── Нет
    Цель достигается ≥ 10 раз в неделю (в кампании или в пакете)?
    ├── Да → «Максимум конверсий»
    │        ├── бюджет ≥ 10 × CPA и важна предсказуемая цена → оплата за конверсии (PAY_FOR_CONVERSION)
    │        └── иначе → оплата за клики с целевой CPA (AVERAGE_CPA)
    │        Несколько равноценных целей → *_MULTIPLE_GOALS
    └── Нет
        ├── Объединить кампании или собрать пакетную стратегию → снова проверить порог
        ├── Выбрать цель выше по воронке (корзина, начало оформления, звонок)
        └── Временно «Максимум кликов» → через 2–4 недели пересмотр
Нужен ручной контроль ставок на поиске → «Максимум кликов с ручными ставками» (в сетях ручных ставок нет)
```

## Корректировки ставок

`BidModifier` — процент от ставки: 100 = без изменений, 0 = −100%, 1300 = +1200%.

| Тип (API) | Диапазон `BidModifier` | В процентах | Примечание |
|-----------|------------------------|-------------|------------|
| `MobileAdjustment` | 0–1300 | −100% … +1200% | можно отдельно для iOS и Android (`OperatingSystemType`) |
| `TabletAdjustment` | 0–1300 | −100% … +1200% | с 2022 |
| `DesktopAdjustment` (компьютеры и Smart TV) | 0–1300 | −100% … +1200% | нельзя обнулить вместе с мобильными |
| `DesktopOnlyAdjustment` | 0–1300 | −100% … +1200% | только компьютеры |
| `SmartTvAdjustment` | см. документацию | — | добавлена 26.10.2025 |
| `DemographicsAdjustments` | 0–1300 | −100% … +1200% | пол и/или возраст, до 12 на кампанию или группу |
| `RetargetingAdjustments` | 0–1300 | −100% … +1200% | условия ретаргетинга, до 100 |
| `RegionalAdjustments` | 10–1300 | −90% … +1200% | только на уровне кампании |
| `VideoAdjustment` | 50–1300 | −50% … +1200% | видеодополнения |
| `SerpLayoutAdjustments` | 1–1300 | −99% … +1200% | эксклюзивное размещение (`ALONE`), саджест (`SUGGEST`) |
| `IncomeGradeAdjustments` | 1–1300 | −99% … +1200% | платёжеспособность: `VERY_HIGH`, `HIGH`, `ABOVE_AVERAGE` |
| `AdGroupAdjustment` | 1–1300 | −99% … +1200% | только для групп ЕПК |

Метод `bidmodifiers.toggle` отключён 13.11.2025: чтобы выключить корректировку — `delete` или `set` со значением 100.

## Рекомендации аудита

- **YD49:** стратегия соответствует цели и объёму конверсий — по дереву выше.
- **YD50:** недельный бюджет ≥ 300 ₽; для оплаты за конверсии ≥ 10 × CPA.
- **YD51:** `BidCeiling`, целевые CPA и ДРР не задушены: недорасход при растущем CPA — сигнал ослабить ограничения.
- **YD28:** ручные ставки на поиске + короткие фразы без операторов = неконтролируемый охват.
- **YD55:** не менять стратегию, тип ограничения и модель оплаты во время обучения.
